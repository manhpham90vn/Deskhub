## Nothing to redo

Deskhub 9.2.0 speaks the same authentication version as every 9.0 and 9.1 release, so
hosts and clients on any 9.x release talk to each other and no device has to be let in
again. Coming from 8.x or older, read the
[9.0.1 notes](https://github.com/manhpham90vn/Deskhub/releases/tag/v9.0.1) first: every
device must be on Deskhub 9.

What is new is on the Windows host, so update the Windows machine you connect **to**; the
viewer needs nothing new.

## ⚠️ Windows: the setup file is now the only download

- **The portable `deskhub-v*-windows.exe` is gone.** Everything that reaches the secure
  desktop — UAC prompts, the lock screen, and now the sign-in screen — runs inside the
  *DeskHub Secure Desktop* service that only the setup installs, so a Windows app without
  it would ship half-working. Download `deskhub-v9.2.0-windows-setup.exe` or use
  `winget install ManhPham.Deskhub`; a portable exe you kept from 9.1 keeps working
  as before, without the new feature. The CLI's portable `deskhub-cli-v*-windows.exe` is
  unchanged.

## ✨ New

- **Reach a Windows PC right after it starts, before anyone signs in.** Tick *Allow access
  before anyone signs in* in Settings → Host. From then on, whenever DeskHub is not
  sharing — at the sign-in screen after a reboot, after you sign out, after you quit the
  app — the *DeskHub Secure Desktop* service runs a host of its own. A device already on
  your allowed list connects, sees the sign-in screen, types the password and carries on
  into the desktop. The PC answers with the same fingerprint as always, so nothing has to
  be trusted again. When DeskHub itself starts sharing, the service's host steps aside and
  the viewer reconnects to the app within a moment; when the app stops, the service takes
  over again.
- **Only devices you already allowed get in.** The host before sign-in admits exactly the
  keys on your allowed list, approves nobody and shows no requests: pair new devices while
  you are signed in. Removing a device on the Devices page shuts it out of the sign-in
  screen within a second. Ctrl+Alt+Del cannot be sent, so a PC whose policy demands it
  before the password box is not reachable this way.
- **Off by default, and it leaves a trace you should know about.** Turning it on copies
  this PC's key, its allowed list and its sharing settings into `%ProgramData%\DeskHub`, a
  folder only SYSTEM and administrators can open; turning it off deletes the copies, and
  uninstalling removes the folder. Whoever is on the allowed list and knows the Windows
  password can sign in from anywhere that reaches the PC — keep that list short.

## 📦 Packages and building

- **`DeskhubService.exe` gains `--unattended-host`** and links the same Windows host code
  as the app; the service keeps its logs in `%ProgramData%\DeskHub` now, no longer in the
  SYSTEM profile, and `--uninstall` removes that folder.
- **The service's control pipe now starts with a request byte** (`SecureDesktopRequest`
  in `core/session/host/SecureDesktopWire`), and the `Watch` message carries whether the
  agent should stream every desktop and at which fps. Both binaries ship together, so
  nothing on the wire between machines changed.

## Nothing to redo

Deskhub 9.3.3 speaks the same authentication version as every 9.x release, so hosts and
clients on any 9.x release talk to each other and no device has to be let in again.
Coming from 8.x or older, read the
[9.0.1 notes](https://github.com/manhpham90vn/Deskhub/releases/tag/v9.0.1) first: every
device must be on Deskhub 9.

## ✨ New

- **A Linux machine can be reached before anyone signs in.** *Allow access before anyone
  signs in*, until now on Windows and macOS, comes to Linux. Tick it under *Launch* in
  Settings, or run `deskhub-cli settings set unattended=on`. From then on, devices already
  on your allowed list can see the login screen right after the machine starts, type the
  password and carry on into the desktop. They can also reach the machine whenever the app
  is not sharing. The host behind it is `deskhubd`, a new system service that the `.deb`
  and `.rpm` install and start. It does nothing until the setting is on, and it reads the
  screen straight from the graphics card, so it works under any login screen and shows no
  screen-sharing dialog. Only devices already allowed get in, and pairing still happens
  while someone is signed in. Only root or a member of the `sudo`, `wheel` or `admin`
  group can switch it on. It needs Intel or AMD graphics with Mesa; the NVIDIA proprietary
  driver is not supported yet. When the app starts sharing after sign-in, it takes over
  from that host, and a viewer who was watching reconnects to the app's share on its own.
- **`deskhub-cli` switches it on Linux too.** As on Windows, `settings set unattended=on`
  and `off` do what the checkbox does, and the `access` commands keep the host before
  sign-in in step with the allowed list.

## 🐛 Fixes

- **Connecting from Linux no longer closes the app on Wayland.** 9.3.2 sent the
  compositor a malformed request when a viewer window took the keyboard, and GNOME closed
  the app the moment the picture appeared. The Super key now reaches the host as 9.3.2
  intended.

## 📦 Packages and building

- **The Linux packages carry `deskhubd`.** It is installed as
  `/usr/libexec/deskhub/deskhubd` with `deskhubd.service`, enabled and started on install,
  and stopped on removal. Removing the package also deletes `/var/lib/deskhub`, where it
  keeps the copies of your key, allowed list and settings that the host before sign-in
  needs. The packages now depend on `libgbm1`.

## 🔒 Privacy

- The [privacy policy](https://github.com/manhpham90vn/Deskhub/blob/main/PRIVACY.md) is
  now version 2.17. It describes `deskhubd` and the copies it keeps in `/var/lib/deskhub`,
  a folder only root can open. Nothing new is transmitted.

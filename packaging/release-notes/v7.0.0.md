## ⚠️ Breaking changes — update every device

Deskhub 7 replaces passcodes and pairing with key pairs, the way SSH works. A 7.x device
cannot talk to a 6.x device, so update the host and every client together.

- **Passcodes and pairing are gone.** A host now lets in only the client keys you
  allow, and a client connects only to hosts whose key it trusts.
- **Previous pairings are not carried over.** Every client has to be allowed again
  (steps below). Old pairing files are deleted on first launch; nothing is migrated.
- **No LAN discovery.** Connect by typing the host's address (`192.168.1.10`, or
  `192.168.1.10:PORT` off the default 47777).
- **The device name moved to Settings** → *General* → **Device name**. The host and the
  client both use it, and it labels your public key.
- **CLI:** `probe`, `scan`, `--passcode`, `--pairing`, `--no-new-pairings` and
  `--timeout` are removed. New: `key`, `access`, `host`, `host-key` and
  `--accept-new-host-key`.
- **iOS:** settings are kept in a new folder inside the app, so they start from their
  defaults once after updating.

## 🔌 Connecting in 7.x

1. **Client:** open **Devices** → *When this machine is the client* → **My keys** and
   press *Copy public key* beside `default`. Send that line to the host's owner; it is
   safe to share.
2. **Host:** open **Devices** → *When this machine is the host* → **Clients allowed to
   connect to this machine**, paste the line and press *Allow*.
3. **Client:** type the host's address and press *Connect*. A **New host** dialog shows
   the host's fingerprint (`SHA256:…`).
4. **Host:** compare it with **Devices** → **This machine's host key**. If they match,
   press *Trust and connect* on the client. Later connections skip the dialog.

From a terminal:

```sh
deskhub-cli key public --name default | ssh me@host deskhub-cli access add --stdin
deskhub-cli connect 192.168.1.10 --accept-new-host-key
```

`--accept-new-host-key` trusts a host seen for the first time without asking. To pin the
host's key before the first connection instead, pipe `deskhub-cli host-key public` from the
host into `deskhub-cli host add` (see `deskhub-cli help host`).

If the client says its key is not authorized, the host has not allowed it yet; go back
to step 2. Full guide: [Keys and access](https://github.com/manhpham90vn/Deskhub/blob/main/docs/INSTALL.md#-keys-and-access).

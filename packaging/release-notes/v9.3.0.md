## Nothing to redo

Deskhub 9.3.0 speaks the same authentication version as every 9.x release, so hosts and
clients on any 9.x release talk to each other and no device has to be let in again.
Coming from 8.x or older, read the
[9.0.1 notes](https://github.com/manhpham90vn/Deskhub/releases/tag/v9.0.1) first: every
device must be on Deskhub 9.

What is new is on the macOS host, so update the Mac you connect **to**; the viewer needs
nothing new.

## ⚠️ One download per platform: the CLI now ships inside the app

- **No more `deskhub-cli-*` files.** Every desktop package carries `deskhub-cli`:
  - **Windows** — `deskhub-v9.3.0-windows-setup.exe` installs `deskhub-cli.exe` beside the
    app and puts that folder on the machine `PATH`, so the command works in any new
    terminal. Setup removes an earlier separate *DeskHub CLI* install on the way in.
  - **macOS** — `deskhub-v9.3.0-macos.dmg` carries it inside the app at
    `Deskhub.app/Contents/MacOS/deskhub-cli`; `brew install --cask manhpham90vn/tap/deskhub`
    links it into `PATH`. The `deskhub-cli` Homebrew formula is retired — run
    `brew uninstall deskhub-cli` once if you had it.
  - **Linux** — `deskhub-v9.3.0-amd64.deb` and `deskhub-v9.3.0-x86_64.rpm` install
    `/usr/bin/deskhub` and `/usr/bin/deskhub-cli` together and replace the old
    `deskhub-cli` package on upgrade; the apt repository serves the one package.
- **The portable Linux binaries and `deskhub-*-licenses.zip` are gone** too: every
  package carries the notices itself. Build from source for a distribution without deb or
  rpm.
- **winget is no longer published**, so there is nothing to `winget install`; download
  the setup file from Releases.

## ✨ New

- **Reach a Mac before anyone signs in.** Tick *Allow access before anyone signs in*
  under *Permissions* on the Settings page. macOS asks you once, under System Settings →
  General → Login Items & Extensions, to allow Deskhub in the background; the app says so
  and offers to open that pane. From then on, whenever nobody is signed in — at the login
  window after a sign-out, and right after a restart when FileVault is off — a device
  already on your allowed list connects, sees the login window, types the password and
  carries on into the desktop. The Mac answers with the same fingerprint as always. Once
  someone signs in, that host stops and only the app shares; keep *Start Deskhub when you
  log in* and *Start sharing when the app opens* on if you want access to continue.
- **It is its own program, with its own permissions.** The host before sign-in is
  `DeskhubDaemon`, carried inside the app. Grant it Screen Recording and Accessibility in
  System Settings — the Settings page shows what it found the last time it ran. With
  FileVault on, a restarted Mac waits at the disk-unlock screen, where nothing runs, so
  only sign-outs are covered there.
- **Only devices you already allowed get in,** exactly as on Windows: the login window
  host admits the keys on your allowed list, approves nobody and shows no requests.
  Turning the setting on copies this Mac's key, its allowed list and its sharing settings
  into `/Library/Application Support/Deskhub`, a folder only root can open; turning it
  off deletes the copies and unregisters the daemon. `brew uninstall --zap deskhub`
  removes the folder; after a drag-to-Trash uninstall, delete it yourself.

## 📦 Packages and building

- **`DeskhubDaemon`** is a new CMake target (`deskhub_daemon`) built by the Xcode project's
  CMake phase and embedded by `scripts/embed-macos-daemon.sh`, which also signs it and the
  CLI with the app's identity; `make verify-macos` and CI check both.
- **The pieces Windows and macOS share moved down a layer:** the process-wide
  `UnattendedMode()` flag (`deskhubp/host/UnattendedMode`), the machine-folder helper
  (`deskhubp/system/MachineFolder`), the configuration the app hands over
  (`deskhubp/host/UnattendedPush`), a Unix socket helper (`deskhubp/net/LocalSocket`) and
  the byte-by-byte request parser the daemon uses (`core/session/host/UnattendedControl`),
  each with tests. The control stream gains a `Status` request the Windows service refuses.
- **Privacy policy 2.16** describes the macOS copies.

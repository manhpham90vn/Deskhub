## Nothing to redo

Deskhub 9.3.0 speaks the same authentication version as every 9.x release, so hosts and
clients on any 9.x release talk to each other and no device has to be let in again. Coming
from 8.x or older, read the
[9.0.1 notes](https://github.com/manhpham90vn/Deskhub/releases/tag/v9.0.1) first: every
device must be on Deskhub 9.

Everything in this release is on Windows; the Linux, macOS, Android and iOS builds carry
no change.

## ⚠️ Windows: one setup file, and nothing on winget

- **`deskhub-cli` now ships inside `deskhub-v9.3.0-windows-setup.exe`.** The setup
  installs `Deskhub.exe`, `deskhub-cli.exe` and the *DeskHub Secure Desktop* service
  together under `Program Files\DeskHub` and puts that folder on the system `PATH`, so
  `deskhub-cli` works in any new terminal. The separate `deskhub-cli-v*-windows-setup.exe`
  and the portable `deskhub-cli-v*-windows.exe` are gone: the service trusts only the
  programs in its own folder, so a CLI installed anywhere else could never use it. An
  earlier per-user install of the old CLI setup is removed by the new setup; your settings
  and keys stay where they are.
- **No more winget.** The `ManhPham.Deskhub` and `ManhPham.DeskhubCLI` packages were never
  merged into winget-pkgs and their pull requests are now closed. The setup file on GitHub
  Releases is the only Windows download, and running a newer one over the old upgrades in
  place.

## ✨ New

- **The command line gets the secure desktop and access before sign-in.** `deskhub-cli
  share` on Windows now goes through the service like the app: viewers see UAC prompts,
  the lock screen and the sign-in screen and can type into them.
  `deskhub-cli settings set unattended=on` turns on *Allow access before anyone signs in*
  — the same setting, the same service — and `access add`, `access remove`,
  `access approve` and `access clear` keep the host before sign-in in step. Run that
  terminal as an administrator: only administrators may talk to the service, and the CLI
  says so when they do not.

## 📦 Packages and building

- **`packaging/windows/DeskhubCLI.iss`, `scripts/publish-winget.sh` and the winget job
  are gone.** The release workflow builds `deskhub-cli.exe` into `Deskhub.iss`, the
  service trusts `deskhub-cli.exe` beside it like `Deskhub.exe`, and the `build-cli`
  Windows job only builds and smokes the exe. Komac is no longer pinned.

## Nothing to redo

Deskhub 9.3.2 speaks the same authentication version as every 9.x release, so hosts and
clients on any 9.x release talk to each other and no device has to be let in again.
Coming from 8.x or older, read the
[9.0.1 notes](https://github.com/manhpham90vn/Deskhub/releases/tag/v9.0.1) first: every
device must be on Deskhub 9.

The change below is on the machine you connect **from**; the host needs nothing new.

## ✨ New

- **The Windows key, Super and ⌘ now reach the host.** While a viewer window has the
  keyboard, that key and every combination with it go to the host instead of the
  viewer's own desktop. Remote into a Mac from Windows or Linux and `Win+C` copies,
  `Win+V` pastes and `Win+Tab` switches apps *there*; until now Windows opened Copilot,
  the clipboard history and Task View instead, and GNOME its launcher. On Windows the
  key pressed alone no longer opens Start. On Linux the viewer holds the keyboard on X11
  and asks Wayland's shortcuts inhibitor, which GNOME may ask you to allow once per
  window. On macOS the ⌘ shortcuts the app's menus used to take first, such as ⌘W, ⌘H
  and ⌘Q, go to the host. What the viewer's OS keeps for itself stays with it: Alt+Tab
  and Ctrl+Alt+Del on Windows, ⌘Tab and ⌘Space on macOS; on Linux everything goes to the
  host, Alt+Tab included, so leave with the mouse, or Super+Esc on GNOME. `Ctrl` still
  arrives as Control, so Ctrl+C in a Mac terminal is still Ctrl+C.

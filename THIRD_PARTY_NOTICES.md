Where they land: the `.deb` and `.rpm` packages of the app and of the command-line client
put this file in `/usr/share/doc/<package>/` and the texts in
`/usr/share/doc/<package>/licenses/` (the LGPL text, for example, at
`/usr/share/doc/deskhub/licenses/LGPL-2.1.txt`); both Windows installers put them beside
the executable, in the install folder and its `licenses` subfolder; the macOS app carries
them in the app bundle's `Contents/Resources`, the iOS app in its bundle, and the Android APK
in its assets. The portable command-line binaries cannot carry anything beside them, so
every release also offers `deskhub-<tag>-licenses.zip` with `LICENSE`, this file and the
whole `licenses/` folder.

### FFmpeg (LGPL-2.1-or-later, statically linked)

The Linux app and the Linux command-line client are the only targets that bundle FFmpeg.
It is built from unmodified upstream FFmpeg 8.0 sources, pinned by checksum, by
[`scripts/build-ffmpeg.sh`](scripts/build-ffmpeg.sh), configured **without**
`--enable-gpl` and **without** `--enable-nonfree`, with only FFmpeg's native H.264
decoder and the VA-API hwaccel enabled. The resulting `libavcodec` and `libavutil` are
therefore covered by the GNU Lesser General Public License, version 2.1 or later — full
text in [`licenses/LGPL-2.1.txt`](licenses/LGPL-2.1.txt).

Because these libraries are linked statically, LGPL-2.1 §6 requires that recipients be
able to relink the application against a modified version of FFmpeg. Deskhub satisfies
this by shipping complete source: the application sources are in this repository under
the MIT License, and `scripts/build-ffmpeg.sh` reproduces the exact FFmpeg build into
`third_party/ffmpeg-min`. Anyone can put their own FFmpeg build there (or change the
script) and rebuild with `make build-linux` / `make release-linux` for the app, or
`make build-cli` / `make release-cli` for the command-line client.

FFmpeg is not modified in any way. Upstream sources: <https://ffmpeg.org/download.html>.

`third_party/nvenc-13.0` is a git submodule containing only the NVIDIA Video Codec SDK
API headers as redistributed by the FFmpeg project under the MIT License. The NVENC
implementation itself lives in the user's NVIDIA driver (`libnvidia-encode.so.1`,
`libcuda.so.1`) and is resolved at runtime; it is not bundled.

### GTK 3 and GLib (LGPL-2.1-or-later, dynamically linked)

Linked dynamically against the distribution-provided shared libraries. No GTK or GLib
source is bundled or modified; users may replace the system libraries freely.

### libayatana-appindicator (dynamically linked, optional)

Used only for the tray icon, and only when the library is present at build time. Upstream
declares the library itself LGPL-2.1 or LGPL-3.0, but a few source files compiled into the
shared library (for example `src/generate-id.c`) carry GPL-3.0 headers. Deskhub links the
distribution's shared library dynamically and does not bundle or modify it.

## Command-line client (`client/cli`)

The command-line client does not use the desktop app's GUI toolkit: there is no GTK
dependency on Linux or wxWidgets dependency on Windows. Like every app it embeds the
QUIC transport and the audio codec listed below.

On Linux it also links the same media stack as the Linux app — FFmpeg **statically**
under the same LGPL-2.1 terms described in the Linux app section above,
plus GLib/GIO, PipeWire, libva, libdrm, libepoxy and EGL dynamically. Its `connect`
command opens a remote-screen window, which needs two libraries the desktop app does not
use:

| Component | License | Linkage |
| --- | --- | --- |
| [libX11](https://gitlab.freedesktop.org/xorg/lib/libx11) | MIT | dynamic (Linux) |
| [libXfixes](https://gitlab.freedesktop.org/xorg/lib/libxfixes) | MIT | dynamic (Linux) |

On Windows it reuses the app's Win32 viewer window, so it adds no new library. On macOS,
the CLI uses AppKit and ScreenCaptureKit from the Apple SDK but does not offer a
remote-screen viewer.

## Patents

H.264/AVC is covered by patents licensed through [Via LA](https://www.via-la.com/).
Patent rights are separate from the copyright licenses above and are not granted by the
MIT License. On Windows, macOS, iOS, and Android, encoding and decoding are performed by
the operating system's own codecs. On Linux, encoding is performed by the GPU vendor's
VA-API driver or by NVIDIA's NVENC driver. Decoding on Linux goes through FFmpeg's H.264
decoder, which Deskhub bundles: with VA-API available the GPU does the decoding, and
without it FFmpeg decodes in software. That FFmpeg decoder is the only H.264
implementation Deskhub ships.

Opus, the audio codec, is also bundled. Opus is published as a royalty-free codec, and the
patent licences that cover it are granted on royalty-free terms — the declarations are
listed in [`licenses/BSD-3-Clause-opus.txt`](licenses/BSD-3-Clause-opus.txt) and at
<https://opus-codec.org/license/>.

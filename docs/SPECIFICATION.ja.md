## 1. 製品概要

Deskhub は、あるマシンが同じネットワーク上の他のマシンに自分の画面を見せ、それらの
マシンからマウスとキーボードを操作させるためのものである。アプリはひとつだけ：同じアプリが
画面を共有もするし、他人の画面を見もする。デスクトップのマシンは**ターミナル**も共有できる。
ホスト上の本物のシェルを、他のマシンが自分のウィンドウで開くというものである（4 章と 5 章）。

インストーラは必須ではなく、アカウントもサインインも常駐サービスもクラウド要素もない。
2 台のマシンは、双方が到達できるネットワーク上の IP アドレスで互いを見つける。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| **ホスト** | 画面（またはターミナル）を共有されている側のマシン。 |
| **クライアント** / **ビューア** | ホストを見ている、場合によっては操作もしているマシン。 |
| **ソース** | ホスト上の共有可能なもの 1 つ：ディスプレイ、またはターミナル。ホストは複数を同時に共有できる。 |
| **セッション** | 1 人のビューアが 1 つのソースを見ている状態。ソースごとに専用のウィンドウが開く。 |
| **鍵** | マシンが初回起動時に作る暗号的な身元。人にはフィンガープリント（`SHA256:…`）として示される。 |
| **ペアリング** | ホストがマシンを恒久的に入れること。ペアリング済みのマシンは鍵で認識され、忘れられるまでパスコードなしで接続できる（9 章）。 |
| **パスコード** | 未知のマシンがペアリングする前に、ホストが要求できる任意の 4 桁のコード。 |

1 台のマシンが同時にホストでもクライアントでもありうる。

## 3. プラットフォーム別の役割

| プラットフォーム | ホスト可 | 視聴可 | 音声 |
| --- | :--: | :--: | :--: |
| Windows | ✅ | ✅ | ✅ |
| macOS | ✅ | ✅ | ✅ |
| Linux | ✅ | ✅ | ✅ |
| Android | ✅ 閲覧専用 | ✅ | ⚠️ Android 10+ |
| iOS | ✅ 閲覧専用 | ✅ | ⚠️ アプリ音声のみ |

12 章に別段の記載がない限り、クライアントの機能一式はどのプラットフォームでも同じである。
スマートフォンとタブレットは**閲覧専用**でホストする。画面は流すが遠隔入力は決して受け
付けない。どのモバイル OS も、普通のアプリに端末を操作させないからである。

アプリはどこでも同じ名前の区画に分かれている：**Host**、**Client**、**Settings** —
それに、このマシンとペアリング済みのマシンを並べる **Devices** 画面（9 章）。

デスクトップ 3 種にはコマンドラインクライアントもある。画面をまったく持たないまま同じ
振る舞いを提供する。ホストになり、接続し、リモートシェルを開き、マシンを探し、アプリと
まったく同じ設定・ペアリング済みマシン・信頼済みホスト鍵を読み書きする。本書に書かれた
振る舞いの別の顔であって、別の振る舞いではない。

## 4. ホストになる — このマシンの画面を共有する

| ID | 機能 | 説明 |
| --- | --- | --- |
| H-1 | ディスプレイ選択 | 共有の前に、このマシンのどのディスプレイを見せるかをチェックする。最低 1 つは必要。 |
| H-2 | 複数ディスプレイ共有 | 複数のディスプレイを同時に共有できる。それぞれが別のソースになり、ビューアが選ぶ。 |
| H-3 | ソース上限 | 同時に共有できるディスプレイは最大 **8** 枚。それ以上ある場合は、最初の 8 枚だけが共有されると警告される。 |
| H-4 | 共有の開始 / 停止 | 1 つの操作で開始、1 つで停止。現在の状態は常に表示される（*Not sharing* / *Starting share…* / *Sharing*）。 |
| H-5 | 1 枚だけ停止 | 共有中のディスプレイを 1 枚だけ、共有全体を終わらせずに止められる。 |
| H-6 | 接続情報 | 共有中、アプリはこのマシンのネットワークアドレスと、ビューアが使うポートを一覧する。読み上げたりコピーしたりできる。デスクトップでは *Share on network* の選択（T-9）がこの一覧の隣、共有画面上にあり、一覧には選んだネットワークのアドレスだけが出る — *All networks* ならすべて出る。共有中（または開始中）はこの選択はロックされる。変えるには共有を止める。 |
| H-7 | ライブセッション表 | 共有中の各ディスプレイについて、ホストには次が見える：ディスプレイ名、解像度、ビューア数、キャプチャレート、送信レート、使用帯域、往復時間。接続中のビューアはそれぞれディスプレイの下に 1 行として現れ、名前を設定していれば（C-7）表示名とアドレス —「名前 (ip:port)」— で、していなければアドレスだけで識別される。 |
| H-8 | ビューアを切断する | ホストはセッション表から任意のビューアを個別に落とせる。 |
| H-9 | ビューア上限 | 1 台のホストを同時に見られるのは最大 **5** 人。それを超える試みは busy として拒否される。 |
| H-10 | 失敗の報告 | 共有を開始できない場合、黙って失敗するのではなく理由が表示される。ポートが埋まっていて起動できないターミナルは、まさにそう言う。 |
| H-11 | ターミナルソース（デスクトップ） | ソース一覧には **Terminal — このマシンのシェル** も並ぶ。一覧を表示するたびに新たにチェックが入り、保存はされない。画面だけ、ターミナルだけ、両方、どれも有効である。すべてはアプリの唯一の UDP ポート（T-4）、パスコード、ネットワーク選択を共有する。 |
| H-12 | 表の中のシェルセッション | ターミナル共有中、ライブ表には *Terminal* の行（ポート付き）が出て、開いている各シェルがその下にビューアと同じ形式（C-7）で 1 行ずつ並び、*Disconnect* が付く。*Terminal* 行の *Stop* はターミナル共有だけを終える。同時に開けるシェルは最大 **8** 個。シェルの開始・終了・再接続・期限切れはすべて、クライアントのアドレス・名前・鍵とともにセッションログ（G-3）に書かれる。 |
| H-13 | シェルは切断に耐える | 接続が切れたシェルは **2 分間**生かされ、同じマシンが中身をそのままに再接続できる。それを過ぎると破棄される。クライアントは自力で再接続する：ホストがまだシェルを保持しているであろう間、間隔を広げながら再試行し、その間は再接続中である旨を表示し、同じシェルを中身とスクロールバックごと取り戻す。2 分が尽きたときにだけ接続喪失を報告し、やり直しを提案する。 |
| H-15 | アイドルなシェルは切れたシェルではない | 通信のないターミナル接続はクライアントが生かし続けるので、プロンプトで放置されたシェルが切断と誤解されて閉じられることはない。 |
| H-16 | ファイル転送ソース（デスクトップ） | ソース一覧には **File transfer — ビューアが送るファイル** も並ぶ。一覧を表示するたびに新たにチェックが入り、保存はされない。ターミナル（H-11）と同様に、アプリの唯一の UDP ポート（T-4）、パスコード、ネットワーク選択を共有する。ファイルは選択欄の下と共有ステータス（T-25）に示されたフォルダに届く。1 バッチは最大 **32** ファイル、1 ファイル **8 GiB**、合計 **32 GiB**。それを超えるもの、保存できない名前は理由付きで拒否される。各ファイルは最終的な名前の隣に `.deskhub-part` を付けて書かれ、丸ごと届いてチェックサムが一致したときにだけ改名される。壊れたファイルは捨てられ、そのバッチは止まる。何も上書きされない：フォルダに既にある名前には番号が付く。フォルダに書き込めない場合はファイルを一切受け取らず、黙って失敗する代わりにホストがそう言う。 |
| H-17 | 表の中の転送 | ファイル転送の共有中、ライブ表にはフォルダ名を示す *File transfer* の行が出て、現在送信中の各マシンがその下にビューアと同じ形式（C-7）で並び、受信中のファイル、バッチ内の位置、完了した割合 — またはバッチが止まった理由 — が表示される。*File transfer* 行の *Stop* はファイル転送だけを終える。バッチの申し出・受理・拒否・完了はすべて、マシンのアドレス・名前・鍵とともにセッションログ（G-3）に書かれる。 |
| H-14 | 停止して引き取る（デスクトップ） | シェルの各行は — 生きているものも再接続待ちのものも — **Stop & attach** も提供する。リモートのクライアントは切断され（その窓はシェル終了を報告する）、まったく同じシェルがホスト上のターミナルウィンドウに、中身とスクロールバックそのままに開く。以後そのシェルはホストのものになる：古いクライアントは再接続できず、2 分の制限（H-13）は適用されなくなり、表の行は *attached on this machine* と記され、ホストの窓を閉じる — または行の *Stop* — でシェルが終わる。この引き取りはセッションログ（G-3）に書かれる。 |

## 5. 接続する — 他のマシンを見る

| ID | 機能 | 説明 |
| --- | --- | --- |
| C-1 | アドレスで接続 | ホストの IP アドレスを一方の欄に、UDP ポートをもう一方（既定の `47777` が入っている）に入力する。アドレス欄に `192.168.1.10:47777` を貼り付けても動く — 明示されたポートがポート欄より優先する。不正な入力は失敗ではなく、説明つきのヒントになる。 |
| C-2 | パスコード入力 | パスコード欄は空でよい。入力する場合はちょうど 4 桁でなければならず、そうでなければ何も送る前に接続が拒まれる。欄に見えているものがそのまま使われる — ユーザーの知らないところで何かが埋められることはない。空のままなら判断はホストがする：ペアリング済みのマシンはそのまま入れ、未ペアリングのマシンは（1 分ほど）待たされ、その間にホストの前の人が入れるかどうか尋ねられる（S-2）。入力したコードをホストが拒めば、パスコードだと分かるメッセージで失敗する。デバイス一覧から開くプロンプトには、その端末の UDP ポートと記憶したパスコード（D-7）が、どちらも編集可能な形で入っている。 |
| C-3 | 操作しない選択 | 接続前に、ビューアは *control the remote machine* のチェックを外して、入力を一切送らずに見るだけにできる。入力を一切受け付けないホスト — スマートフォンやタブレット（P-4）、または入力を切って共有しているデスクトップ — は、何を共有しているか尋ねられたときにそう答え、デスクトップのクライアントはそうしたホストに対して操作もターミナルも効かない旨の注記を常に表示する。 |
| C-4 | ソース選択 | ホストが複数のディスプレイを共有していれば、どれを見るか尋ねられる。複数選べば複数の窓が開く。ちょうど 1 枚なら即座に開く。 |
| C-5 | はっきりした失敗 | ホストに到達できない、共有していない、パスコードを拒まれた — そのどれなのかがアドレス名入りで伝えられる。 |
| C-6 | セッション終了の通知 | どちら側から終わった場合でも、ビューアには理由が表示される。 |
| C-7 | ビューア名 | 接続画面の *Your name* 欄がこの端末に名前を付ける。ユーザーが最初に名前を設定するまではプラットフォーム既定値が入る：Windows と Linux ではコンピュータのホスト名（無ければログインユーザー名）、macOS ではコンピュータ名、iOS では端末名、Android では端末のモデル名。欄は編集でき、接続時に入っているものがそのまま保存され送られる。未設定になることは決してない：空にして接続すると上記の既定値に戻り、それが欄に入り直し、保存され送られる。だから接続には常に名前が伴う。ホストはこのマシンのアドレスの隣に名前を表示し、ビューアを見分けられるようにする。名前はこの端末に記憶され、最大 **64** バイトのテキストで、制御文字は取り除かれる。古いバージョンのホストは単に表示しないだけである。 |
| C-8 | シェルを開く | *Terminal — open a shell* は、ホストが応答したあと（C-10）にどのクライアントにも現れるボタンである。シェルは専用の窓で開き — グリッド、スクロールバック、ステータス行、スマートフォンでは追加のキー列（Esc、Tab、ラッチする Ctrl/Alt、矢印、^C）— その窓はシェルが開けなかった理由（パスコード違い、拒否、到達不能）も表示する。画面を見ながらシェルを動かすのは普通のことである。どのクライアントも何かを開く前にホストが何を共有しているかを知る：ターミナルのないホスト — スマートフォンやタブレット、あるいは共有していないデスクトップ — に対してはボタンが無効のままなので、ターミナルの窓はそもそも開かない。 |
| C-9 | ファイルを送る | どのクライアントも、受け取っているホストにファイルを送れる。*File transfer — send files to it* は、ホストが応答したあと（C-10）にどのクライアントにも現れるボタンで、**Send files** の画面を開く。Android と iOS ではシステムの写真ピッカーかファイルブラウザから選び、送る前にアプリ自身のキャッシュにコピーが置かれる。一度に 1 バッチだけ：実行中はピッカーが無効になり、2 つ目の申し出は busy として拒否される。進捗は送信中のファイル、バッチ内の位置、完了した割合を示し、いつでも中止できる。決着すると、バッチ内の全ファイルが送信済みか否かを理由付きで一覧する。どのクライアントも何かを開く前にホストが何を共有しているかを知る：ファイルを受け取らないホストに対してはボタンが無効のままで、窓は開かない。 |
| C-10 | 接続してから選ぶ | Connect は認証だけを行う：ホストにダイヤルし、ペアリングかパスコードを片付け（S-2）、何を共有しているか尋ねる。応答したホストが差し出すものはどこでも同じである：そのアドレス、**Disconnect** の操作、V-7 のライブ行、そして *Remote desktop — view its screen*、*Terminal — open a shell*、*File transfer — send files to it* のボタンが 1 つずつ。それぞれホストがその機能を共有しているときだけ有効になる。セッションを開くときは今片付けたペアリングを再利用するので、ホスト側の人が二度尋ねられることはない。それらがどこに現れるかはプラットフォームで異なる（C-11）。 |
| C-11 | ホスト 1 台につき 1 つの窓（デスクトップ） | Windows、Linux、macOS では、応答したホストが自分専用の**接続ウィンドウ**を開く。タイトルはそのアドレスで、C-10 の内容をすべて収める。接続画面自体は状態を変えない：アドレス、ポート、パスコード、名前の各欄、Connect、デバイス一覧はそのまま残るので、最初のホストを開いたまま次のホストにダイヤルでき、1 台のマシンが複数のホストに同時につながれる。既に窓のあるホストに再度接続すると、2 つ目を開くのではなくその窓が前面に出る。接続ウィンドウを閉じる、あるいはその **Disconnect** は、そのホストだけを切り、他はそのままにする。アプリを終了すればすべて閉じる。窓から既に開かれたセッション（V-1、C-8、C-9）はそれぞれ独立した窓で、窓より長生きする。Android と iOS では接続は一度に 1 つで、接続画面に留まる：Connect が成功するまで画面は各欄と Connect とデバイス一覧だけ — それ以外はない。ホストが応答するとそれらは C-10 の内容に入れ替わり、Disconnect、またはアドレス・ポート・パスコードの編集で最初の状態に戻る。 |

## 6. マシンを見つける

| ID | 機能 | 説明 |
| --- | --- | --- |
| D-1 | ネットワークスキャン | クライアントはローカルネットワークを走査して、現在共有中のマシンを一覧する。走査中は進捗（「*m* 件中 *n* 件のアドレスを確認」）が出る。何も見つからないときは、あるマシンが出てこない理由 — 共有中のときだけ現れる — が伝えられる。 |
| D-2 | 走査範囲 | 1 回の走査はローカルサブネットの最大 **512** アドレスを対象にする。ローカルネットワークアドレスがないマシンでは、走査できない旨が伝えられる。 |
| D-3 | 自動再走査 | 走査は定期的に繰り返され、*Refresh now* で任意に再実行できる。 |
| D-4 | クリックで接続 | 見つかった端末をクリックすると、そこへの接続が始まる。 |
| D-5 | 最近の端末 | 過去に接続したマシンは *Devices* 一覧に最大 **10** 件保持され、*Where* 列に *Recent* と記され、アドレス、状態、ping、最後に接続した時刻が表示される。 |
| D-6 | ライブ状態 | 各端末には **Online**、**Offline**、**Checking…** のいずれかと往復時間が表示され、**30 秒**ごとに自動で、また任意に更新される。 |
| D-7 | 記憶したパスコード | 端末に使ったパスコードはその端末とともに記憶され、デバイス一覧から接続するときプロンプトに埋められる — 編集可能な欄に見える形でであり、黙って使われることはない。コードを打たずに接続しても記憶したものは消えず、新しいコードを打てば置き換わる。難読化して保存されるが、それは利便性であって保護ではない（9 章を参照）。マシンがペアリングされればコードは重要でなくなる：鍵で認識されるからである。 |
| D-8 | 端末を忘れる | 最近の端末は一覧から削除できる。 |

## 7. セッションを見る

| ID | 機能 | 説明 |
| --- | --- | --- |
| V-1 | ウィンドウに合わせる | リモート画面は縦横比を保ったままウィンドウに合わせて拡縮され、開くときはソースに合わせた大きさになる。デスクトップでは、セッション中に映像の形が本当に変わったとき — スマートフォンやタブレットのホストが回転した、形の違うディスプレイに切り替わった — ウィンドウが新しい形に合わせ直す。形が同じままの画質変化ではウィンドウは動かない。 |
| V-2 | ズームとパン | ビューは最大 **5 倍**までズームでき、パンもできる。ズーム倍率は表示され、1 操作でリセットできる。 |
| V-3 | セッション状態 | ウィンドウにはライブのステータス行が出る：フレームレート、帯域、往復時間、エンドツーエンド遅延。 |
| V-4 | タイトル付きの窓 | 各ビューアウィンドウのタイトルは、表示しているソースと現在の状態なので、複数のセッションを見分けられる。 |
| V-5 | 切断 | ビューアはいつでもセッションを終えられる。 |
| V-6 | 音 | 双方のマシンが対応していれば（3 章）、共有されているマシンが鳴らしている音が、映像とおよそ 1 フレーム以内のずれでビューアに聞こえる。音は専用のチャンネルで運ばれる：パケットを 1 つ落としても失うのは音声の何分の一秒かで、映像を乱すことはなく、何も鳴っていないマシンは帯域をほとんど使わない。切ったビューアには届かず（T-23）、切ったホストは決して送らない（T-22）。 |
| V-7 | 接続の健全性 | この表示はホストに応答があった場所 — デスクトップでは接続ウィンドウ、Android と iOS では接続画面（C-11） — にあり、セッションの窓の中ではない：ホストのアドレス、**Disconnect** の操作（V-5）、そして接続中である旨のライブ行と、その隣に ping が出て、そのホストが応答しなくなった瞬間に赤くなる。表示はデバイス一覧を埋めるのと同じ毎秒 1 回のプローブから来るので、セッションを開く前から存在し、いくつも開いている間も残る。デスクトップでは開いているホストごとに 1 つずつ持つ。ホストを見失ったセッションの窓は、再接続中である旨を表示し続ける（V-8）。 |
| V-8 | 自動再接続 | ホストを見失ったセッション — ネットワークが切れた、映像が止まった — は終わらない。窓は最後の絵を保ち、再接続中であると表示し、バックオフしながら最大 1 分間ダイヤルし直す。ホストが再び応答すれば映像はひとりでに再開する。その 1 分が過ぎたとき、あるいはホストが意図的にセッションを終えるか拒否したときにだけ、窓は理由とともに閉じる。シェルの窓は従来どおり 2 分の再接続猶予を持つ。 |

## 9. アクセス制御と安全性

| ID | 機能 | 説明 |
| --- | --- | --- |
| S-1 | 暗号化 | セッションは暗号化トランスポート（QUIC/TLS）の上を走る。セッションが運ぶすべて — 映像、制御、入力、クリップボード、ターミナルの通信 — は 2 台の間を暗号化されて流れる。探索ビーコンは設計上平文で、秘密を運ばない。それ以外の非暗号のパケットがポートに届いたら捨てられる。全体像は [`SECURITY.ja.md`](../SECURITY.ja.md) にある。 |
| S-2 | 入場はペアリングで決まる | マシンが初めて接続したとき、入れるかどうかはホストが決める。ホストのパスコードを差し出したマシンは、それを知っていることを暗号的に証明する — コード自体はネットワークを流れない。コードを差し出さないマシン — あるいは照合するコードを持たないホスト — は代わりにホストの前の人に回される：*このマシンを入れますか？*、**Allow** と **Deny** つきで、1 回の答えがそのマシンの開こうとするすべて（画面もシェルも）に効く。入れることは 2 台を**ペアリング**することであり、以後そのマシンは鍵で認識され、忘れられるまでパスコードなしで接続できる。ただし入力されたコードは常に検査される — ペアリング済みのマシンでも、間違ったコードを出せば追い返される。 |
| S-3 | 任意のパスコード、ペアリング済み一覧 | パスコードは任意で既定は空。空のままなら、ホストの前の人が承認しない限り何も入れない。ペアリング済みのマシンは **Devices** 画面に並ぶ — 名前、鍵、ペアリング時刻、最終確認時刻 — *Forget* と *Forget every machine*、オフにするとペアリング済みのマシンだけを入れる *allow new pairings* スイッチ、そして読み上げ用にこのマシン自身の鍵つきで。ホストが何を共有しているかは、入場を認めたマシンにしか明かさない。 |
| S-4 | 失敗を重ねるとロック | パスコードを **3** 回間違えると、ホストのペアリングは **30 秒**それ以上の試行を受け付けなくなり、試みているマシンには待つよう伝えられる。ペアリング済みのマシンは影響を受けない。 |
| S-5 | 操作スイッチ | ホストは *viewers can control this machine* を切って共有でき、その場合ビューアが何を求めてもすべてのセッションが閲覧専用になる。 |
| S-6 | キャプチャへの同意 | 必要なプラットフォームでは OS 自身の許可プロンプトと画面選択ダイアログが使われる。ユーザーが許可しない限り Deskhub はキャプチャできない。 |
| S-7 | 共有は明示的にだけ | ユーザーが共有を開始するまで何も共有されない。閉じるか停止すればすべてのセッションが終わる。 |
| S-8 | 鍵変更の警告 | クライアントは信頼したすべてのホストの鍵を覚えている。その鍵が変われば — 中間者はその形をしている — 新しいフィンガープリントを示す目立つ警告が出て、ユーザーが明示的に受け入れるまで接続は拒まれる。一度も見たことのない鍵はペアリングのハンドシェイク自体で片付き、何も尋ねられない。 |

## 10. 設定

設定はマシンごとで、再起動をまたいで保持され、次に共有を開始したときに効く。スマートフォンと
タブレットが出すのはネットワークポート（T-4）— これはネットワーク走査がどのポートを叩くかも
決める — とクリップボード同期（T-17）、スリープ防止（T-19）、それに共有画面上のパスコード
（T-5）と共有するネットワーク（T-9）だけで、それ以外は組み込みの既定値でホストする。

| ID | 機能 | 説明 |
| --- | --- | --- |
| T-7 | 自動画質 | 設定された範囲内で、ストリームの画質が利用可能なネットワーク容量にひとりでに適応する。状況が変わってもユーザーの操作は要らない。 |
| T-8 | 検証 | 範囲外や数値でない値は拒否され、適用ではなく従来の値が保たれる。 |
| T-10 | ネットワークのフォールバック | 特定のネットワークを選んでいると（T-9）、ホストはそのアドレス経由でしか到達できない。共有開始時にそのアドレスがもう存在しなければ、ホストはすべてのネットワークで共有し、その旨を共有ステータスに表示する。保存されているが現在使えないアドレスも、*not connected* と記して一覧に残る。 |
| T-12 | 起動時の自動共有 | デスクトップのみ。T-11 がオンなら、アプリを開くとそのまま Host 画面へ行き、保存された設定で共有を開始する。ユーザーが Share を押したのとまったく同じである。ログイン時にアプリが起動される場合（T-13）、デスクトップにまだディスプレイがないことがある。そのときの共有は待機し、0.5 秒ごとに最大 30 秒まで再確認して、ディスプレイが現れた瞬間に始まる。それまで Host 画面は待機中と表示する。ディスプレイが最後まで現れなければ、チェックされている他のもの（ターミナル）を共有するか、理由を Host 画面に出して何もしない — 自動共有は決してダイアログを開かない。ログイン時のウィンドウはトレイに隠れていて誰にも見えないかもしれないからである。プラットフォームの規則は変わらず適用される：Linux は初回にデスクトップの画面共有ダイアログを出し、以後は記憶した選択を再利用し（P-3）、macOS は相変わらず権限を要求する（P-2）。 |
| T-14 | ログイン時に起動 | デスクトップのみ。T-13 がオンのとき：Linux は `~/.config/autostart` に自動起動エントリを書き、Windows は *Deskhub* という名のスケジュールタスクを登録してログオン時にアプリを昇格して起動する（したがって UAC のプロンプトは出ない）。macOS はユーザーがシステム設定でも見られるログイン項目を登録する。オフにするとその成果物も消える。チェックボックスは最後に保存した値ではなく、OS が報告する状態を常に示す。 |
| T-16 | バックグラウンドモード | デスクトップのみ。T-15 がオンだと、*Show/Hide window*、*Start/Stop sharing*、*Quit* を持つトレイ / メニューバーのアイコンが出る。ウィンドウを閉じてもアプリは終了せず隠れ、共有はバックグラウンドで続く。ウィンドウは起動時に必ず現れ、ユーザーが閉じたときにだけ隠れるので、T-13 + T-11 + T-15 を組み合わせると、ログイン時に共有が始まり、閉じるまでウィンドウは表示されたままになる。Windows ではトレイアイコンの左クリックでウィンドウが出入りする。macOS ではウィンドウが隠れている間 Dock のアイコンが消える。Linux ではトレイに StatusNotifier ホストが要る（KDE は標準、GNOME は AppIndicator 拡張が必要）— それがなければウィンドウを閉じるとやはり終了するので、アプリが到達不能になることはない。Windows と Linux では共有中にウィンドウを閉じると、T-15 がオフでも（トレイが使えるなら）必ずトレイに隠れるので、接続中のビューアが切られることはない。macOS ではウィンドウを閉じてもアプリは終了しないので、どちらにせよ共有は続く。 |
| T-18 | クリップボード同期 | T-17 がオンなら、セッション内のどのマシンでコピーしたプレーンテキストも、数秒のうちに他のマシンに現れる。双方向で、ホストはあるビューアのコピーを他のビューアにも中継する。テキストの上限は 32 KiB（それより長いコピーは文字境界で切られる）。画像、ファイル、書式は決して転送されない。ホストのトグルがセッションを支配する：オフなら、ホストはクリップボードのデータを無視し、決して送らない。各マシンは自分のローカルクリップボードを読み書きするために、自分のトグルもオンにする必要がある。Android と iOS では OS が制約する：Android 端末は Deskhub が前面にあるときだけ自分のコピーを拾う（届いたテキストはいつでも適用される）。iOS のビューアは Deskhub が新しいコピーを読むときにシステムのペーストプロンプトを出すことがある。ホストになっている iOS 端末はまったく参加しない。ブロードキャストがクリップボードにアクセスできない別プロセスで動くからである。 |
| T-20 | スリープ防止 | T-19 がオンなら、共有中や視聴中にマシンはスリープせず、ディスプレイも消えない。セッションが終わった瞬間にブロックは解除され、スリープ設定は一切変更されない。Windows、macOS、Linux ではホストにもビューアにも、ディスプレイとシステム両方のスリープを覆う（Linux では systemd-logind と、freedesktop のスクリーンセーバーインターフェースを尊重するデスクトップが要る — KDE と GNOME は標準）。OS が譲らないところでは OS が勝つ：ノート PC の蓋を閉じる、電源ボタンを押す、macOS のバッテリー駆動などでは、なおスリープしうる。Android と iOS では、このトグルはストリーム視聴中に画面を点けたままにする。スマートフォンからの共有は元々画面が消えても続く（P-5）ので、そちらのホストは画面を保持しない。 |
| T-25 | ファイルの届き先 | デスクトップのみ。ビューアが送るファイルは、このマシンが選んだフォルダ — 別途選ばない限りユーザーのホームフォルダの `Deskhub` — に書かれる。選んだフォルダは共有前にファイル転送のチェックの隣に、共有中は共有ステータスに表示され、存在しなければ作られ、他の設定とともに保存される。そのフォルダの外には決して書かれない：送り手側の名前は最後のパス要素まで削られ、ローカルのファイルシステムが保存できないものは除去される。 |
| T-24 | 共有される音とは | T-22 がオンなら、ホストは自分のスピーカーが鳴らしているもの — その上のすべてのアプリが出す音のミックス — を共有する。マイクは決してキャプチャしない：Deskhub に双方向音声はない。権限が絡む唯一のプラットフォームが Android で、その再生キャプチャ API はシステムが*マイク*と表示する権限の後ろにある。アプリは共有開始時にそれを求め、他の用途には使わない。拒否すれば音なしで共有が進む。他のどのプラットフォームもマイク権限を求めない。ビューアは自分が求めた場合にだけ音を受け取る（T-23）ので、T-22 がオンのホストも聴いていないビューアには何も送らない。どちらのトグルも次にセッションが始まるときに効く。 |

## 12. プラットフォーム固有の振る舞い

| ID | プラットフォーム | 振る舞い |
| --- | --- | --- |
| P-1 | Windows | アプリは起動時に一度だけ管理者権限を求める。昇格されたウィンドウに入力できるのはそのためである。共有を始めるときには自分でファイアウォール規則を追加する。 |
| P-2 | macOS | *画面収録*（共有に必要）と*アクセシビリティ*（遠隔入力の受け入れに必要）の現在の許可状態、それぞれを要求するボタン、システム設定へのショートカットを持つ **Permissions** パネルを表示する。アクセシビリティが未許可だと、一部のキー入力は macOS に黙って遮られる。 |
| P-3 | Linux | Host 画面は他のデスクトップと同じく、このマシンのディスプレイとターミナルをチェックボックスで並べ、チェックしたディスプレイだけが共有される。Share を押した後、デスクトップは自分の画面共有ダイアログで改めてキャプチャを確認する。デスクトップが対応していれば（ScreenCast portal のバージョン 4 以降）その確認は記憶され、以後の共有は再起動をまたいでも黙って再利用するので、ダイアログは初回だけ出る。デスクトップが許可した内容がチェックしたディスプレイとまったく合わない場合、記憶した確認は忘れられ、ダイアログがもう一度出て、正しいディスプレイを許可できる。デスクトップが確認を拒否したか期限切れにした場合 — コンポジタの更新やモニタの変更の後 — は単にダイアログがまた出るだけで、キャンセルしても再試行はしない。デスクトップが許可したディスプレイをチェック済み一覧に対応づけられない場合は、何も共有しないのではなく、許可されたものすべてを共有する。ターミナルだけをチェックすればデスクトップのダイアログは完全に省かれる。共有にはさらに、システムが入力注入を許可していることが必要である。 |
| P-4 | Android / iOS | ホストは**閲覧専用**：端末は画面を流し、制御パケットはすべて黙って捨てる。どちらの OS もアプリにシステム全体への入力注入を許さないからである。ターミナルは共有しない — 尋ねられたらそう答えるので、スマートフォン相手にターミナルの窓を開くクライアントはない（C-8）— し、デスクトップのクライアントは操作のチェックが効かないと伝えられる（C-3）。アプリが画面に出た瞬間から H-16 のバッチ規則でファイルを受け取り、探すべきスイッチはなく、画面の共有中も受け取り続けるので、ビューアは画面を見ながら同時にファイルを送れる。iOS ではブロードキャスト拡張が放送の間ずっと唯一のポートを保持し、そこから両方を提供する。受け取った写真と動画は端末の写真ライブラリに追加される — iOS ではシステムの追加専用の写真権限の後ろで、最初に 1 つ届いたときに求められ、Deskhub に読み取り権限を一切与えず、拒否された場合はファイルが Documents へ行く。Android ではシステムのメディアストア経由で `Pictures/Deskhub` と `Movies/Deskhub` へ。それ以外のファイルはシステムのファイルブラウザから見える場所（iOS ではアプリの Documents、Android では `Download/Deskhub`）に届き、通知が何が来たかを告げる。画面全体がひとつのソースとして共有されるので、ディスプレイ選択、複数ディスプレイ共有、ディスプレイ単位の停止（H-1、H-2、H-3、H-5）は適用されない。端末を回せばストリームも回る：ビューアに見えるものは正しい向きのままで、窓は新しい形に合わせ直す（V-1）。セッションの UI はタッチ優先である：トラックパッドのジェスチャ、ズーム操作、ホットキーバー、オンスクリーンキーボード、ディスプレイ切り替え、そしてシェルとファイル転送の画面と共通の隅の閉じるボタン。 |
| P-5 | Android | 共有にはシステムの画面録画同意ダイアログが必要で、これは共有ごとに与えられ記憶できない。音の共有にはさらに Android が*マイク*と表示する権限が要る — 再生キャプチャ API がその後ろにある — 共有開始時に求められ、拒否すれば音なしで画面が共有される。共有中は継続的な通知が表示され、アプリがバックグラウンドに回っても画面が消えてもストリームは生き続ける。システム通知から共有を止めればセッションは終わる。 |
| P-6 | iOS | 共有はアプリ内の **Start sharing** ボタンから始め、システムのブロードキャストシートを開く。iOS がすべての放送をそのシートで確認するよう求めるためである。別のブロードキャストプロセスで動くので、アプリを閉じても続く。共有画面は接続中のビューア数 — 名前を設定しているものは名前も（C-7）— と、ブロードキャストプロセスの現在のメモリ使用量 — iOS はメモリ上限を超えた放送を終わらせる — を報告するが、H-7 のようなビューア別の表はなく、ビューアを個別に落とすこともできない（H-8）。放送を終わらせるシステムイベント — たとえば着信 — はセッションを終わらせる。 |

## 13. 明示的に対象外

Deskhub は次を提供**せず**、本仕様も扱わない：

- マイクのキャプチャ、双方向音声、あらゆる音声通話チャンネル。音は一方向にしか流れず、
  共有されているマシンから見ている人へ向かうだけである（V-6）。
- リモート印刷。
- プレーンテキストを超えるクリップボード同期（画像、ファイル、リッチテキスト）。
- アカウント、ディレクトリ、プレゼンス、招待の仕組み。
- リレー、ランデブー、NAT 越えのサービス — インターネット越しにホストへ到達するのは
  ユーザーの責任である（たとえば VPN 経由で）。
- セッションの録画。
- 無人アクセス、Wake-on-LAN、遠隔電源制御。
- マルチユーザー管理、ロール、監査証跡。

# Deskhub —— 功能规格说明

本文档描述 Deskhub **做什么**，以使用者的体验为准。这是一份产品规格，不是设计文档：它不
包含实现细节、不描述协议、也没有构建说明。那些内容在
[`INSTALL.zh.md`](INSTALL.zh.md)、[`BUILD.zh.md`](BUILD.zh.md)、
[`SECURITY.zh.md`](../SECURITY.zh.md) 和源码树里。

本文件是 [`SPECIFICATION.md`](SPECIFICATION.md) 的译本；若两者有出入，以英文版为准。

- **状态：** 描述的是当前代码的行为。
- **读者：** 任何需要知道这个产品应该做什么的人 —— 测试者、评审者、贡献者、商店页面。

## 1. 产品概要

Deskhub 让一台机器把自己的屏幕展示给同一网络上的其他机器，并让那些机器操控它的鼠标和
键盘。它只有一个应用：同一个应用既能共享屏幕，也能看别人的屏幕。桌面机器还能共享一个
**终端**：主机上一个真实的 shell，其他机器在自己的窗口里打开它（第 4、5 节）。

不要求安装程序，没有账号，不用登录，没有后台服务，也没有云端组件。两台机器通过彼此都能
到达的网络上的 IP 地址找到对方。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **主机（Host）** | 屏幕（或终端）被共享出去的那台机器。 |
| **客户端（Client）** / **观看者（Viewer）** | 正在看主机、并可选地控制它的那台机器。 |
| **来源（Source）** | 主机上一个可共享的东西：一块显示器，或者终端。一台主机可以同时共享多个。 |
| **会话（Session）** | 一个观看者看一个来源。每个来源在自己的窗口里打开。 |
| **密钥（Key）** | 机器首次运行时创建的密码学身份，以指纹形式展示给人看（`SHA256:…`）。 |
| **配对（Pairing）** | 主机把一台机器长期放进来。已配对的机器凭密钥被识别，无需通行码即可连接，直到被忘记（第 9 节）。 |
| **通行码（Passcode）** | 主机可选要求的 4 位数字码，陌生机器要先过这一关才能配对。 |

同一台机器可以同时是主机和客户端。

## 3. 各平台的角色

| 平台 | 能做主机 | 能观看 | 声音 |
| --- | :--: | :--: | :--: |
| Windows | ✅ | ✅ | ✅ |
| macOS | ✅ | ✅ | ✅ |
| Linux | ✅ | ✅ | ✅ |
| Android | ✅ 仅只读 | ✅ | ⚠️ Android 10+ |
| iOS | ✅ 仅只读 | ✅ | ⚠️ 仅应用音频 |

除非第 12 节另有说明，每个平台提供的客户端功能集都相同。手机和平板以**只读**方式做主机：
它们推流自己的屏幕，但从不接受远程输入，因为没有哪个移动系统允许普通应用操控设备。

应用在各处都按同样的命名分区组织：**Host**、**Client** 和 **Settings** —— 外加一个
**Devices** 页面，列出与本机配对的机器（第 9 节）。

三个桌面系统还有一个命令行客户端。它提供同样的行为，只是完全没有页面：它能做主机、能
连接、能打开远程 shell、能找机器，并且读写的正是应用所用的那份设置、已配对机器和受信任
主机密钥。它是本文档所述行为的另一副面孔，绝不是另一套行为。

## 4. 做主机 —— 共享本机屏幕

| ID | 功能 | 描述 |
| --- | --- | --- |
| H-1 | 显示器选择 | 共享之前，用户勾选要暴露本机的哪些显示器。至少要勾一个。 |
| H-2 | 多显示器共享 | 可以同时共享多块显示器；每块成为一个独立来源，观看者在其中挑选。 |
| H-3 | 来源上限 | 最多可同时共享 **8** 块显示器。机器超过这个数时，会提示用户只有前 8 块会被共享。 |
| H-4 | 开始 / 停止共享 | 一个动作开始共享，一个动作停止。当前状态始终显示（*Not sharing* / *Starting share…* / *Sharing*）。 |
| H-5 | 停掉单块显示器 | 可以停掉某一块已共享的显示器，而不结束整个共享。 |
| H-6 | 连接信息 | 共享期间，应用列出本机的网络地址和观看者要用的端口，方便念出来或复制。桌面端的 *Share on network* 选择（T-9）就在这份列表旁边的共享页面上，列表只显示所选网络的地址 —— 选 *All networks* 则显示全部地址。正在共享（或正在开始共享）时该选择被锁定；要改就先停止共享。 |
| H-7 | 实时会话表 | 每块共享的显示器，主机都能看到：显示器名称、分辨率、观看者数量、采集帧率、发送帧率、占用带宽和往返时延。每个已连接的观看者在其显示器下自成一行，以其显示名和地址标识 ——「名字 (ip:port)」—— 观看者设了名字时（C-7）如此，否则只显示地址。 |
| H-8 | 踢掉一个观看者 | 主机可以从会话表里踢掉任意一个观看者。 |
| H-9 | 观看者上限 | 同一时间最多 **5** 个观看者可以看一台主机。更多的尝试会以「忙」被拒绝。 |
| H-10 | 失败上报 | 如果共享无法开始，会把原因显示给用户，而不是默默失败。因为端口被占而起不来的终端会明说是这个原因。 |
| H-11 | 终端来源（桌面） | 来源列表里还有 **Terminal —— 本机上的一个 shell**。每次显示列表时它都重新勾选一遍、从不保存；只共享屏幕不共享终端、只共享终端不共享屏幕，或者两个都共享，都是合法的。所有这些共用应用的那一个 UDP 端口（T-4）、通行码和网络选择。 |
| H-12 | 表里的 shell 会话 | 终端被共享期间，实时表里会有一行 *Terminal*（带它的端口），每个打开的 shell 在它下面各占一行，标识方式和观看者一样（C-7），并带 *Disconnect*；*Terminal* 那一行的 *Stop* 只结束终端共享。最多同时开 **8** 个 shell。每个 shell 的打开、关闭、重新接入或过期，都会连同客户端的地址、名字和密钥写进会话日志（G-3）。 |
| H-13 | shell 扛得住掉线 | 连接断掉的 shell 会被保活 **2 分钟**，好让同一台机器带着会话内容重新接上；超时之后才丢弃。客户端会自己重连：只要主机还会留着这个 shell，它就以递增的间隔重试，重试期间会说明自己正在重新接入，并把同一个 shell 连同内容和回滚历史接回来。只有那 2 分钟耗尽了，它才报告连接已丢失，并提供重新开始的选项。 |
| H-15 | 空闲的 shell 不是掉线的 shell | 没有流量的终端连接由客户端保活，所以停在提示符上不动的 shell 不会被误判成断链而关掉。 |
| H-16 | 文件传输来源（桌面） | 来源列表里还有 **File transfer —— 观看者发来的文件**，每次显示列表时重新勾选、从不保存；它和终端一样（H-11）共用应用的那一个 UDP 端口（T-4）、通行码和网络选择。文件落在选择器下方以及共享状态里标明的那个文件夹中（T-25）。一批最多 **32** 个文件、单文件 **8 GiB**、总量 **32 GiB**；超出的、或者名字无法存储的，会带着原因被拒绝。每个文件先以最终名字加 `.deskhub-part` 后缀写在旁边，只有完整抵达且校验和匹配后才改名；损坏的文件会被丢掉并中止这一批。任何东西都不会被覆盖：文件夹里已有的同名文件会被加上编号。如果那个文件夹写不了，就一个文件都不收，主机会明说，而不是默默失败。 |
| H-17 | 表里的传输 | 文件传输被共享期间，实时表里会有一行 *File transfer* 标明文件夹，每台正在发送的机器在它下面各占一行，标识方式和观看者一样（C-7），显示正在接收的文件、它在这一批里的位置和已完成的比例 —— 或者这一批中止的原因。*File transfer* 那一行的 *Stop* 只结束文件传输。每一批的提出、接受、拒绝或完成，都会连同机器的地址、名字和密钥写进会话日志（G-3）。 |
| H-14 | 停止并接管（桌面） | 每一行 shell —— 无论是活着的还是在等重新接入的 —— 都还提供 **Stop & attach**：远端客户端被断开（它的窗口报告 shell 已结束），而同一个 shell 会在主机上的终端窗口里打开，内容和回滚历史完好无损。从此这个 shell 归主机机器所有：旧客户端无法再接入，2 分钟上限（H-13）不再适用，表里那一行标记为 *attached on this machine*，关掉主机那个窗口 —— 或者点那一行的 *Stop* —— 就结束这个 shell。这次接管会写进会话日志（G-3）。 |

## 5. 连接 —— 观看另一台机器

| ID | 功能 | 描述 |
| --- | --- | --- |
| C-1 | 按地址连接 | 用户在一个字段里输入主机的 IP 地址，在另一个字段里输入 UDP 端口，端口预填默认值 `47777`。把 `192.168.1.10:47777` 粘进地址栏也照样管用 —— 它里面显式写的端口优先于端口字段。无效输入会给出解释性提示，而不是失败。 |
| C-2 | 通行码输入 | 通行码字段可以留空。输入的码必须正好 4 位数字，否则在发出任何东西之前连接就会被拒。字段里显示什么，用的就是什么 —— 不会在用户背后自动填任何东西。留空时由主机决定：已配对的机器直接放行；未配对的则等待（大约一分钟），期间会去问主机前的人要不要放它进来（S-2）。输入的码被主机拒绝时，失败消息里会点明是通行码的问题。从设备列表打开的提示框会显示该设备的 UDP 端口和记住的通行码（D-7），两者都预填且可编辑。 |
| C-3 | 放弃控制权 | 连接之前，观看者可以取消勾选*控制远程机器*，只看不发任何输入。完全不接受输入的主机 —— 手机或平板（P-4），或者关闭了输入的桌面共享 —— 在被问到共享了什么时会说明这一点，桌面客户端还会常驻一条说明，指出面对这样的主机时控制和终端都不起作用。 |
| C-4 | 来源选择 | 如果主机共享了不止一块显示器，会问观看者要看哪一块。选多块就开多个窗口。如果主机只共享一块，就直接打开。 |
| C-5 | 明确的失败原因 | 如果主机连不上、没在共享，或者拒绝了通行码，会告诉观看者是哪一种 —— 消息里会点出地址。 |
| C-6 | 会话结束提示 | 会话结束时，无论从哪一端结束，观看者都会看到原因。 |
| C-7 | 观看者名字 | 连接页面上的 *Your name* 字段为本设备命名。在用户第一次设置名字之前，它按平台预填默认值：Windows 和 Linux 上是计算机的主机名（没有主机名时用登录用户名），macOS 上是电脑名称，iOS 上是设备名，Android 上是设备型号。这个字段可以编辑，连接时里面是什么，保存和发送的就是什么。它永远不会变成未设置：字段被清空后再连接，会回落到上面那个平台默认值，重新填回字段，并作为保存和发送的内容，所以每次连接总会带着一个名字。主机会把名字显示在本机地址旁边，好把观看者区分开。名字记在本设备上，最多 **64** 字节文本，其中的控制字符会被去掉。跑旧版本的主机只是不显示它而已。 |
| C-8 | 打开一个 shell | *Terminal —— open a shell* 是一个按钮，主机应答之后（C-10）在每个客户端上都会出现。shell 在自己的窗口里打开 —— 字符网格、回滚历史、状态行，手机上还有额外一排按键（Esc、Tab、可锁定的 Ctrl/Alt、方向键、^C）—— 那个窗口也会说明 shell 为什么打不开（通行码错、被拒、连不上）。一边看屏幕一边跑 shell 是常态。每个客户端在打开任何东西之前都会先弄清主机共享了什么：面对没有终端的主机 —— 手机、平板，或者没共享终端的桌面 —— 按钮保持禁用，所以根本不会开出终端窗口。 |
| C-9 | 发送文件 | 每个客户端都能给正在收文件的主机发文件。*File transfer —— send files to it* 是一个按钮，主机应答之后（C-10）在每个客户端上出现，会打开一个 **Send files** 界面。在 Android 和 iOS 上，文件从系统相册选择器或系统文件浏览器里挑，发送前会在应用自己的缓存里暂存一份副本。一次只能一批：有一批在跑时选择器会被禁用，第二次提出会以「忙」被拒。进度会说明正在发的文件、它在这一批里的位置和已完成的比例，传输随时可以停止。结束时，这一批里的每个文件都会列出发送成功与否，并附原因。每个客户端在打开任何东西之前都会先弄清主机共享了什么：面对不收文件的主机，按钮保持禁用，所以不会开窗口。 |
| C-10 | 先连接，再选择 | Connect 只做认证：它拨号到主机，把配对或通行码的事办完（S-2），然后问主机共享了什么。已应答的主机在各处提供的东西是一样的：它的地址、一个 **Disconnect** 控件、V-7 那条实时状态行，以及各一个按钮 —— *Remote desktop —— view its screen*、*Terminal —— open a shell* 和 *File transfer —— send files to it*，每个只在主机确实共享该能力时才可用。打开会话会复用刚刚办好的配对，所以主机那边不会被第二次询问。这些东西落在哪里因平台而异（C-11）。 |
| C-11 | 每台主机一个窗口（桌面） | 在 Windows、Linux 和 macOS 上，应答的主机会打开一个属于自己的**连接窗口**，标题是它的地址，里面装着 C-10 列出的一切。连接页面本身状态不变：地址、端口、通行码和名字字段、Connect 以及设备列表都待在原处，所以第一台主机还开着时就能拨下一台，一台机器可以同时连多个主机。再次连接一台已有窗口的主机，会把那个窗口提到前面，而不是开第二个。关闭一个连接窗口，或者点它的 **Disconnect**，只断开那一台主机，其他不受影响；退出应用则全部关闭。已经从某个窗口打开的会话（V-1、C-8、C-9）是各自独立的窗口，活得比它更久。在 Android 和 iOS 上一次只有一个连接，而且就留在连接页面上：Connect 成功之前，页面就是那些字段、Connect 和设备列表 —— 别无其他；主机应答之后，这些让位给 C-10 列出的内容，而 Disconnect 或者编辑地址、端口、通行码，都会让页面回到第一种状态。 |

## 6. 找机器

| ID | 功能 | 描述 |
| --- | --- | --- |
| D-1 | 网络扫描 | 客户端扫描本地网络，找出当前正在共享的机器并列出来，扫描时显示进度（"已检查 *m* 个地址中的 *n* 个"）。扫描一无所获时，会告诉用户某台机器为什么可能不在其中：它只在共享时才出现。 |
| D-2 | 扫描范围 | 一次扫描最多覆盖本地子网上的 **512** 个地址。如果机器没有本地网络地址，会告诉用户无法扫描。 |
| D-3 | 自动重新扫描 | 扫描会周期性重复，也可以通过 *Refresh now* 按需重跑。 |
| D-4 | 点击即连 | 点一下发现到的设备就开始连接它。 |
| D-5 | 最近的设备 | 连接过的机器保留在 *Devices* 列表里 —— 最多 **10** 台 —— 在 *Where* 列里标为 *Recent*，并显示地址、状态、延迟和上次连接时间。 |
| D-6 | 实时状态 | 每台最近的设备会显示 **Online**、**Offline** 或 **Checking…** 以及往返时延，每 **30 秒**自动刷新一次，也可按需刷新。 |
| D-7 | 记住的通行码 | 某台设备用过的通行码会跟它一起被记住，从设备列表连接时预填到提示框里 —— 是可见地填在可编辑字段里，绝不悄悄使用。不输码直接连接不会抹掉记住的那个；输入新码则会替换它。它以混淆形式存储，那是为了方便 —— 不是保护（见第 9 节）。机器一旦配对，这个码就不重要了：它们靠密钥被识别。 |
| D-8 | 忘掉一台设备 | 最近的设备可以从列表里移除。 |

## 7. 观看一个会话

| ID | 功能 | 描述 |
| --- | --- | --- |
| V-1 | 适应窗口 | 远端画面按比例缩放以适应窗口，打开时窗口按来源尺寸设置。在桌面端，当画面形状在会话中途真的变了 —— 手机或平板主机转屏，或者切到形状不同的显示器 —— 窗口会重新适配新形状；形状不变、只是画质变化时窗口不动。 |
| V-2 | 缩放与平移 | 视图最多可放大到 **5 倍**并平移。缩放倍数会显示出来，一个动作即可复位。 |
| V-3 | 会话状态 | 窗口显示一条实时状态行：帧率、带宽、往返时延和端到端延迟。 |
| V-4 | 带标题的窗口 | 每个观看窗口的标题是它正在显示的来源加上当前状态，好让多个会话能区分开。 |
| V-5 | 断开 | 观看者随时可以结束会话。 |
| V-6 | 声音 | 在两台机器都支持时（第 3 节），观看者能听到被共享机器正在播放的声音，与画面的同步误差在大约一帧以内。声音走自己的通道：丢一个包只损失几分之一秒的音频，绝不干扰画面，而一台什么都没在播的机器几乎不占带宽。观看者关掉它就没有（T-23），主机关掉它就从不发送（T-22）。 |
| V-7 | 连接健康度 | 这个读数在主机被应答的地方 —— 桌面上是连接窗口，Android 和 iOS 上是连接页面（C-11）—— 而不在会话窗口里：它显示主机地址、一个 **Disconnect** 控件（V-5），以及一条说明已连接的实时状态行，旁边带着延迟，一旦那台主机不再应答就变红。读数来自填充设备列表的那同一个每秒一次的探测，所以会话开之前它就在，多个会话开着时它还在，而在桌面端每台打开的主机各有自己的一份。丢了主机的会话窗口仍然会说自己正在重新接入（V-8）。 |
| V-8 | 自动重连 | 丢了主机的会话 —— 网络掉了、流没声了 —— 不会结束。窗口保留最后一帧画面，说明自己正在重新接入，并以退避策略重拨最多一分钟；主机重新应答时画面自行恢复。只有过了那一分钟，或者主机主动结束、拒绝会话，窗口才带着原因关闭。shell 窗口仍然保有它自己的两分钟重新接入宽限期。 |

## 9. 访问控制与安全

| ID | 功能 | 描述 |
| --- | --- | --- |
| S-1 | 加密 | 会话跑在加密传输（QUIC/TLS）上。会话承载的一切 —— 视频、控制、输入、剪贴板和终端流量 —— 在两台机器之间都是加密传输的。发现信标按设计是明文的，且不携带任何秘密；抵达该端口的任何其他未加密包一律丢弃。完整情况见 [`SECURITY.zh.md`](../SECURITY.zh.md)。 |
| S-2 | 配对把关准入 | 一台机器第一次连接时，由主机决定是否放它进来。提供了主机通行码的机器会以密码学方式证明自己知道这个码 —— 码本身从不经过网络。不提供码的机器 —— 或者主机根本没有码可查 —— 则转给主机前的人：*让这台机器进来吗？*，带 **Allow** 和 **Deny**，一次回答覆盖那台机器正在打开的一切（屏幕和 shell 都算）。放它进来就是把两台机器**配对**：从此它凭密钥被识别，无需通行码即可连接，直到被忘记。不过输入的码总是会被检查 —— 即便是已配对的机器，提供了错误的码也会被挡回去。 |
| S-3 | 可选通行码、已配对列表 | 通行码是可选的，默认为空；为空时，没有主机前的人批准就什么都进不来。已配对的机器列在 **Devices** 页面上 —— 名字、密钥、配对时间、最后出现时间 —— 带 *Forget* 和 *Forget every machine*，一个 *allow new pairings* 开关（关掉后只放已配对的机器进来），以及本机自己的密钥供念出来核对。主机只对已放行的机器透露自己共享了什么。 |
| S-4 | 反复失败即锁定 | **3** 次通行码错误会把主机的配对锁上 **30 秒**，不再接受新的尝试，并告诉那台正在尝试的机器等一等。已配对的机器不受影响。 |
| S-5 | 控制开关 | 主机可以在关闭 *viewers can control this machine* 的情况下共享，这样不管观看者请求什么，每个会话都是只读的。 |
| S-6 | 采集需经同意 | 在需要的平台上，使用的是操作系统自己的权限提示和选屏对话框；用户不授权，Deskhub 就无法采集。 |
| S-7 | 只有明确共享才共享 | 用户不启动共享就什么都不共享。关闭或停止会结束所有会话。 |
| S-8 | 密钥变更警告 | 客户端会记住每一台它信任过的主机的密钥。如果那个密钥变了 —— 中间人攻击就是这个形状 —— 会弹出醒目的警告显示新指纹，并拒绝连接，直到用户明确接受。从没见过的密钥由配对握手本身来解决，不会多问。 |

| ID | 功能 | 描述 |
| --- | --- | --- |
| T-7 | 自动画质 | 流的画质会在配置的上下限之内，自行适应可用的网络容量；条件变化时不需要用户做任何事。 |
| T-8 | 校验 | 超范围或非数字的值会被拒绝并保留原值，而不是被应用。 |
| T-10 | 网络回退 | 选定了某个网络时（T-9），主机只能通过那个地址被访问到。如果开始共享时那个地址已不存在，主机会改为在所有网络上共享，并在共享状态里说明。已保存但当前不可用的地址仍会列出，标记为 *not connected*。 |
| T-12 | 启动即共享 | 仅桌面。T-11 打开时，打开应用会直接进 Host 页面并用已保存的设置开始共享，就像用户自己按了 Share 一样。应用在登录时启动（T-13）时，桌面可能还没有任何显示器；这时共享会等待，每半秒重查一次，最多等 30 秒，一有显示器出现就开始。在那之前 Host 页面会说自己在等。如果始终没有显示器出现，应用就共享其他勾选的东西（终端），或者闲着并在 Host 页面上说明原因 —— 自动共享绝不弹对话框，因为登录时窗口可能藏在托盘里没人看得见。平台规则依然适用：Linux 第一次会显示桌面的屏幕共享对话框，之后复用记住的选择（P-3），而 macOS 仍然要求它的那些权限（P-2）。 |
| T-14 | 登录时启动 | 仅桌面。T-13 打开时：Linux 会在 `~/.config/autostart` 里写一条自启动条目；Windows 注册一个名为 *Deskhub* 的计划任务，在登录时以提权方式启动应用，因此不会弹 UAC；macOS 注册一个用户也能在系统设置里看到的登录项。关掉它就把那个产物再删掉。这个勾选框始终显示操作系统报告的状态，而不只是上次保存的值。 |
| T-16 | 后台模式 | 仅桌面。T-15 打开时，会出现一个托盘 / 菜单栏图标，带 *Show/Hide window*、*Start/Stop sharing* 和 *Quit*；关闭窗口是把应用藏起来而不是退出，共享在后台继续。窗口在启动时总会出现，只有用户关闭它时才隐藏，所以 T-13 + T-11 + T-15 三个合起来的效果是：登录时开始共享，窗口一直显示到被关闭为止。在 Windows 上，左键点托盘图标会显示或隐藏窗口。在 macOS 上，窗口隐藏期间 Dock 图标会消失。在 Linux 上托盘需要一个 StatusNotifier 宿主（KDE 标配；GNOME 需要 AppIndicator 扩展）—— 没有它时关闭窗口仍然是退出，这样应用就永远不会变得够不着。在 Windows 和 Linux 上，共享进行期间关闭窗口总是隐藏到托盘，即使 T-15 是关的（只要有托盘可用），以免已连接的观看者被断开；在 macOS 上关闭窗口从来不会退出应用，所以两种情况下共享都继续。 |
| T-18 | 剪贴板同步 | T-17 打开时，会话中任何一台机器上复制的纯文本，会在几秒内出现在其他机器上，双向都行；主机会把某个观看者的复制内容转发给其他观看者。文本上限 32 KiB（更长的复制会在完整字符处截断）；图片、文件和格式永远不会传输。主机的开关决定整个会话：它关着时，主机既忽略也从不发送剪贴板数据。每台机器还需要自己的开关也打开，才能读写本地剪贴板。在 Android 和 iOS 上操作系统会有限制：Android 设备只有在 Deskhub 处于前台时才能取到自己这边的复制内容，不过收到的文本任何时候都会应用；iOS 上的观看端在 Deskhub 读取新复制内容时可能弹出系统粘贴提示；而正在做主机的 iOS 设备完全不参与，因为它的广播跑在一个没有剪贴板访问权限的独立进程里。 |
| T-20 | 保持唤醒 | T-19 打开时，机器在共享或观看期间不会睡眠，显示器也不会关闭；会话一结束就解除阻止，而且不会改动任何睡眠设置。在 Windows、macOS 和 Linux 上，这对主机和观看者都同时覆盖显示器睡眠和系统睡眠（Linux 上需要 systemd-logind 和一个遵守 freedesktop 屏保接口的桌面 —— KDE 和 GNOME 标配）。操作系统坚持的地方它仍然赢：合上笔记本盖子、按电源键，或者 macOS 用电池供电时，机器仍可能进入睡眠。在 Android 和 iOS 上，这个开关在观看流的时候保持屏幕常亮；手机做主机时本来就扛得住息屏（P-5），所以那边做主机不会保持屏幕常亮。 |
| T-25 | 文件落在哪里 | 仅桌面。观看者发来的文件写进本机选定的一个文件夹 —— 除非另选，否则是用户主目录下的 `Deskhub`。所选文件夹在共享前显示在文件传输勾选框旁边，共享期间显示在共享状态里；不存在就创建，并与其他设置一起保存。那个文件夹之外的任何地方都不会被写入：发送方的名字会被剥到最后一个路径元素，并清洗掉本地文件系统存不了的任何东西。 |
| T-24 | 共享的是什么声音 | T-22 打开时，主机共享的是它自己的扬声器正在播放的东西 —— 它上面所有应用产生的混音。它从不采集麦克风：Deskhub 没有双向音频。Android 是唯一涉及权限的平台 —— 它的播放采集 API 藏在系统标为*麦克风*的那个权限后面，应用在共享开始时申请它，且不作他用；拒绝它，共享照样进行，只是没有声音。其他平台都不申请麦克风权限。观看者只有主动要了才会收到声音（T-23），所以 T-22 打开的主机不会给没在听的观看者发任何东西，而两个开关都在下一次会话开始时生效。 |

## 12. 各平台的特有行为

| ID | 平台 | 行为 |
| --- | --- | --- |
| P-1 | Windows | 应用在启动时申请一次管理员权限，正是它让应用能往提权窗口里打字。共享开始时它会自行添加防火墙规则。 |
| P-2 | macOS | 显示一个 **Permissions** 面板，展示*屏幕录制*（共享所需）和*辅助功能*（接受远程输入所需）的实时授权状态、各自的申请按钮，以及一个通往系统设置的快捷方式。未授予辅助功能时，某些按键会被 macOS 悄悄拦掉。 |
| P-3 | Linux | Host 页面像其他桌面一样，把本机的显示器和终端列成勾选框，只有勾上的显示器才会被共享。按下 Share 之后，桌面仍然会用它自己的屏幕共享对话框确认一次采集；在桌面支持的地方（ScreenCast portal 版本 4+）那次确认会被记住：之后的共享静默复用它，跨重启也有效，所以对话框只在第一次出现。如果桌面授予的内容与勾选的显示器完全对不上，记住的确认会被忘掉、对话框再显示一次，好让用户授予正确的显示器；如果桌面拒绝了或确认已过期 —— 比如合成器升级或换了显示器之后 —— 对话框就再出现一次，而取消它绝不会重试。如果桌面授予的显示器应用无法与勾选列表对应，就共享桌面授予的全部，而不是什么都不共享。只勾终端则完全跳过桌面对话框。共享另外还要求系统允许输入注入。 |
| P-4 | Android / iOS | 做主机是**只读**的：设备推流自己的屏幕，并静默丢弃每一个控制包，因为这两个系统都不允许应用在系统层面注入输入。它不共享终端 —— 被问到时会这么说，所以没有客户端会对着手机开终端窗口（C-8）—— 而桌面客户端可以据此说明勾选控制不会有任何作用（C-3）。从应用出现在屏幕上那一刻起它就开始收文件，遵循 H-16 的批次规则，没有开关要找，而且在屏幕被共享期间会继续收，所以观看者可以一边看屏幕一边给它发文件；在 iOS 上，广播扩展在整个广播期间持有那一个端口，并用它同时服务这两件事。收到的照片和视频会被加进设备的相册 —— 在 iOS 上要经过系统的仅添加相册权限，第一次收到文件时申请，绝不给 Deskhub 任何读取权限，被拒绝时文件改放 Documents；在 Android 上则通过系统媒体库放进 `Pictures/Deskhub` 和 `Movies/Deskhub`。其他文件落在系统文件浏览器能看到的地方（iOS 上是应用的 Documents 文件夹，Android 上是 `Download/Deskhub`），并有一条通知说明来了什么。整个屏幕作为单一来源被共享，所以显示器选择、多显示器共享和按显示器停止（H-1、H-2、H-3、H-5）都不适用。转动设备，画面也跟着转：观看者看到的始终是正的，他们的窗口会重新适配新形状（V-1）。会话界面以触摸为先：触控板手势、缩放控件、快捷键条、屏幕键盘、显示器切换器，以及角落里一个与 shell 和文件传输界面共用的关闭按钮。 |
| P-5 | Android | 共享需要系统的屏幕录制同意对话框，它按每次共享授予且无法被记住；共享声音另外还需要 Android 标为*麦克风*的那个权限 —— 它的播放采集 API 被挡在它后面 —— 在共享开始时申请；拒绝它就共享无声的屏幕。共享期间会显示一条持续通知，而且应用进入后台或屏幕关闭时流仍然存活。从系统通知里停止共享会结束会话。 |
| P-6 | iOS | 共享从应用内的 **Start sharing** 按钮开始，它会打开系统的广播面板，因为 iOS 要求用那个面板确认每一次广播，并且跑在一个独立的广播进程里，所以应用关闭后它仍然继续。共享界面报告已连接的观看者数量 —— 列出其中设了名字的（C-7）—— 以及广播进程当前的内存占用（iOS 会结束超出内存上限的广播），但没有 H-7 那样的逐观看者表格，观看者也无法被单独踢掉（H-8）。结束广播的系统事件 —— 比如来电 —— 会结束会话。 |

## 13. 明确不在范围内

Deskhub **不**提供，本规格也不涵盖：

- 麦克风采集、双向音频，或任何语音通道。声音只单向流动，从被共享的机器流向看它的人
  （V-6）。
- 远程打印。
- 纯文本以外的剪贴板同步（图片、文件、富文本）。
- 任何账号、目录、在线状态或邀请系统。
- 中继、会合或 NAT 穿透服务 —— 通过互联网够到主机是用户自己的责任（例如通过 VPN）。
- 会话录制。
- 无人值守访问、网络唤醒或远程电源控制。
- 多用户管理、角色或审计轨迹。
